## Learned User Preferences

- Prioritize skin treatments over hair in design and content hierarchy; hair should be visually secondary.
- Avoid generic AI-slop aesthetics; Stitch “Clinical Serenity” theme (Manrope + Work Sans, warm teal `#005f56`, secondary brown `#765842`, soft surface bands)—not cream + serif editorial templates.
- Verify hero and layout fixes in real browsers (Chrome/Edge), not only the Cursor embedded browser.
- Navbar: clinic logo mark plus single-line wordmark with full `clinic.nameShort` (not split `wordmarkLine1`/`wordmarkLine2`); `.glass-nav` white frosted bar; desktop links Treatments, Hair restoration, Dermatology, Results, Contact with `.btn-nav-cta` Book appointment; below `lg`, compact header with smaller mark, icon-only `.nav-book-mobile` calendar CTA, hamburger, and Staff login only inside the mobile menu (Ask a question / Location / Call stay in the menu or footer—not crowded into the header).
- Hero: prefer the hybrid frosted-bottom layout—full-bleed clinic photo dominant, subtle bottom/left `.hero-overlay` only (no full pale wash), bottom-aligned `.hero-bottom-band` with compact frosted `.hero-main-card` (copy/CTAs) and combined `.hero-info-card` (location/hours); reject vertically centered full-overlay heroes that hide the interior; on mobile keep receptionist/sign visible and avoid cards covering the photo subject.
- Primary hero CTA uses `.btn-primary` (teal); secondary hero action uses `.btn-secondary-outline` (warm brown border).
- Floating CTAs: only `.whatsapp-float` as an icon-only compact circle (bottom-right; never bottom-left); no floating Book appointment button.
- Section CTAs must be real buttons with consistent alignment; one primary conversion path to `#contact`, not per-card booking spam; harden the public site for mobile (touch targets, spacing, full-width CTAs where needed); multi-column card grids (e.g. CareStandards, SocialProof) should stretch to equal card heights.
- Public Staff login links to the separate admin app (production `/admin` on same domain, local dev port 5174); admin treats patient form data as read-only—staff may update status and internal notes only.
- Doctor bio/credentials should follow NMC registration details and `https://drprakashacharya.com.np/` as source of truth; keep Pokhara clinic primary (Kathmandu/Reva practice is secondary context only).
- Do not edit attached plan files when implementing plans; follow existing todos without recreating them.
- After substantive changes, commit and push to GitHub (`origin/main`) every time unless the user says otherwise.
