## Learned User Preferences

- Prioritize skin treatments over hair in design and content hierarchy; hair should be visually secondary.
- Avoid generic AI-slop aesthetics; Stitch “Clinical Serenity” theme (Manrope + Work Sans, warm teal `#005f56`, secondary brown `#765842`, soft surface bands)—not cream + serif editorial templates.
- Verify hero and layout fixes in real browsers (Chrome/Edge), not only the Cursor embedded browser.
- Navbar: clinic logo mark plus single-line wordmark with full `clinic.nameShort` (not split `wordmarkLine1`/`wordmarkLine2`); `.glass-nav` white frosted bar; desktop links Treatments, Hair restoration, Dermatology (`#doctor`), Results, Contact with `.btn-nav-cta` Book appointment; below `lg`, compact header with smaller mark, icon-only `.nav-book-mobile` calendar CTA, hamburger, and Staff login only inside the mobile menu (Ask a question / Location / Call stay in the menu or footer—not crowded into the header).
- Hero: prefer the hybrid frosted-bottom layout—full-bleed clinic photo dominant, subtle bottom/left `.hero-overlay` only (no full pale wash), bottom-aligned `.hero-bottom-band` with compact frosted `.hero-main-card` (copy/CTAs) and combined `.hero-info-card` (location/hours stacked vertically); reject vertically centered full-overlay heroes that hide the interior; on mobile keep receptionist/sign visible, avoid cards covering the photo subject, and keep the photo edge-to-edge (no right gap); never replace the main homepage hero image unless the user explicitly asks.
- Primary hero CTA uses `.btn-primary` (teal); secondary hero action uses `.btn-secondary-outline` (warm brown border).
- Floating CTAs: only `.whatsapp-float` as an icon-only compact circle (bottom-right; never bottom-left); no floating Book appointment button.
- Service/promo photographs (e.g. Exosomes spotlight, treatment product shots) must show the full frame—no crop or chop; prefer `object-fit: contain` over cover when the user supplies a composed graphic. Treatment and Hair restoration cards must use curated photos from `public/images/treatments/{skin,hair,aesthetic}`—never reuse Outcomes before/after assets from `public/images/results/`.
- Section CTAs must be real buttons with consistent alignment; one primary conversion path to `#contact`, not per-card booking spam; booking preferred date must block past days (calendar + submit validation); harden the public site for mobile (touch targets, spacing, full-width CTAs where needed); multi-column card grids (e.g. CareStandards, SocialProof) should stretch to equal card heights; Outcomes before/after cards should stay visually substantial.
- Public Staff login links to the separate admin app (production `/admin` on same domain, local dev port 5174); admin treats patient form data as read-only—staff may update status and internal notes only; Gallery, Results, and Services admin tables need thumbnail preview columns so staff can tell which image is which.
- Doctor bio/credentials follow NMC registration details and `https://drprakashacharya.com.np/` as source of truth; keep Pokhara clinic primary (Kathmandu/Reva practice is secondary context only); TrustStrip below the hero is clinic-focused (place/hours/care scope)—NMC/MD/publications belong in ClinicDoctor, not that strip.
- Do not edit attached plan files when implementing plans; follow existing todos without recreating them. After substantive changes, commit and push to GitHub (`origin/main`, `catalyixacademia-hash`) every time unless the user says otherwise.

## Learned Workspace Facts

- Single-page marketing site: React 19, Vite 7, Tailwind CSS 4, Framer Motion; no client-side router; public build uses `vite-plugin-singlefile`; admin is a separate Vite app in `admin/` (dev port 5174); production deploys via `vercel.json` (public at root, admin SPA at `/admin`, `pokhara-skin-and-hair-clinic.vercel.app`); GitHub repo `catalyixacademia-hash/pokhara-skin-and-hair-clinic`.
- Stitch design tokens live in `src/index.css` (background `#f9f9fc`, surface `#ffffff`, ink `#1a1c1e`, primary `#005f56`, primary-container `#0d7a6f`, secondary `#765842`; Manrope headlines + Work Sans body; type scale `--text-display/h1/h2/h3`, elevation `--shadow-1..4`, fluid `--section-y`, `--ease-out`). `src/utils/cn.ts` registers custom `text-*` sizes separately from `text-*` colours so `text-h2` is not dropped when combined with `text-ink`.
- Public section order: Hero → TrustStrip (clinic highlights: place/hours/care scope—not doctor credentials) → ExosomesSpotlight (`#exosomes`, first-in-Pokhara Exosome skin/hair claim; keep related SEO in `index.html`) → Treatments (`#services` skin cards + `#hair-services` compact rows) → CareStandards → ClinicDoctor (`#doctor`) → Outcomes (`#results`) → Aesthetics (`#aesthetics`) → Gallery (`#gallery`) → SocialProof (`#testimonials`) → Faq → ClinicJourney (`#about`) → Visit (`#contact`) → GeneralEnquiry (`#enquiry`, `#location`) → Footer → WhatsAppFloat. Adjacent sections must alternate surface / surface-container-low.
- Treatment presentation encodes skin-first hierarchy: skin uses image-led `TreatmentCard` (4 on mobile, 6 from `sm`, rest behind `.disclosure-btn`); hair and aesthetics use compact `TreatmentRow`. Both live in `src/components/ui/TreatmentCard.tsx` with a stretched heading-button (`::after` inset 0)—never nest an `<article>`/`<h3>` inside a `<button>`. Public site prefers curated local treatment photography over CMS/Pexels seeds; image paths under `public/images/treatments/{skin,hair,aesthetic}`.
- Gallery is a snap-scrolling horizontal rail below `sm` and a grid from `sm` up; CMS can hold many photos, so stacking them costs ~2,000px of mobile scroll—do not show a duplicate “Front desk & product wall” hero crop in Gallery. Outcomes (`#results`) falls back to paired before/after assets in `public/images/results/` (`acne`, `peel`, `hair` × before/after `.webp`) when CMS cases are empty. Curated treatment and results assets sync to Supabase Storage `clinic-media` with matching `services`/`results` image URLs.
- `useActiveSection` drives nav state from scroll position (reading line at `navHeight + 96`), not from click; direct measurement beats IntersectionObserver because tall sections otherwise win permanently.
- Clinic business content is centralized in `src/data/clinic.ts` with CMS overrides via `clinic_settings` (maps, WhatsApp float/main URLs, social/reviews URLs, phones); brand assets `/clinic-logo-mark.png` and `/favicon.png` (both still ~92KB identical PNGs—needs offline resize); floating WhatsApp and form handoff use `whatsappFloat` (9706929329).

No. 12549 (Specialist, Dermatology), MD Dermatology Kathmandu University (2020), MBBS Tribhuvan University Maharajgunj Medical Campus (2011), site `https://drprakashacharya.com.np/`; portrait at `/images/doctor/dr-prakash-acharya.png`.
- Hero: same reception photo at every breakpoint—`clinic-hero@1920.jpg` at `lg`+, WebP derived from that frame below `lg`, `clinic-hero.jpg` as no-WebP fallback (never a different clinic shot). Media-scoped `index.html` preloads. Mobile `.hero-media`: do not combine `aspect-ratio` with `max-height` (browsers shrink width and leave a right gap); size height from viewport width (`min(32rem, calc(100vw * 4 / 3))`), force `width: 100%`; `picture` / `.hero-bg-image` absolute-fill with `object-fit: cover` and `max-width: none`; matching ratio-derived `padding-top` on `.hero-shell`; `object-position` ~42–46% mobile / ~56% 38% desktop keeps sign and receptionist in frame.
- Public booking (`#contact`) and enquiry (`#enquiry`) persist to `appointments` with `form_type`, send Resend emails, then open prefilled WhatsApp via `src/lib/whatsapp.ts`; forms use borderless `.field-input` on surface-container-low inside `.form-card`; map is a plain Google Maps embed iframe.

Admin routes: `/dashboard`, `/queue`, `/bookings`, `/enquiries`, `/analytics`, `/treatment-options`, `/settings`, `/services`, `/testimonials`, `/results`, `/gallery`, `/hero`, `/doctor`; login via `src/lib/admin-url.ts`; WA scripts in `admin/src/lib/follow-up-scripts.ts`; CMS singletons `clinic_settings` and `doctor_profile` (id=1) use `.maybeSingle()` with upsert-on-empty.
- Framer Motion hero entrance must not spread undefined `transition` when reduced motion is on (`…undefined` throws “is not iterable”); only pass motion props when animation is enabled.
