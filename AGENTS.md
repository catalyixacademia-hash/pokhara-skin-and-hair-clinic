## Learned User Preferences

- Prioritize skin treatments over hair in design and content hierarchy; hair should be visually secondary.
- Avoid generic AI-slop aesthetics; Stitch “Clinical Serenity” theme (Manrope + Work Sans, warm teal `#005f56`, secondary brown `#765842`, soft surface bands)—not cream + serif editorial templates.
- Verify hero and layout fixes in real browsers (Chrome/Edge), not only the Cursor embedded browser.
- Navbar: clinic logo mark plus single-line wordmark with full `clinic.nameShort` (not split `wordmarkLine1`/`wordmarkLine2`); `.glass-nav` white frosted bar; desktop links Treatments, Hair restoration, Dermatology (`#doctor`), Results, Contact with `.btn-nav-cta` Book appointment; below `lg`, compact header with smaller mark, icon-only `.nav-book-mobile` calendar CTA, hamburger, and Staff login only inside the mobile menu (Ask a question / Location / Call stay in the menu or footer—not crowded into the header).
- Hero: prefer the hybrid frosted-bottom layout—full-bleed clinic photo dominant, subtle bottom/left `.hero-overlay` only (no full pale wash), bottom-aligned `.hero-bottom-band` with compact frosted `.hero-main-card` (copy/CTAs) and combined `.hero-info-card` (location/hours stacked vertically); reject vertically centered full-overlay heroes that hide the interior; on mobile keep receptionist/sign visible and avoid cards covering the photo subject.
- Primary hero CTA uses `.btn-primary` (teal); secondary hero action uses `.btn-secondary-outline` (warm brown border).
- Floating CTAs: only `.whatsapp-float` as an icon-only compact circle (bottom-right; never bottom-left); no floating Book appointment button.
- Section CTAs must be real buttons with consistent alignment; one primary conversion path to `#contact`, not per-card booking spam; booking preferred date must block past days (calendar + submit validation); harden the public site for mobile (touch targets, spacing, full-width CTAs where needed); multi-column card grids (e.g. CareStandards, SocialProof) should stretch to equal card heights.
- Public Staff login links to the separate admin app (production `/admin` on same domain, local dev port 5174); admin treats patient form data as read-only—staff may update status and internal notes only.
- Doctor bio/credentials should follow NMC registration details and `https://drprakashacharya.com.np/` as source of truth; keep Pokhara clinic primary (Kathmandu/Reva practice is secondary context only).
- Do not edit attached plan files when implementing plans; follow existing todos without recreating them.
- After substantive changes, commit and push to GitHub (`origin/main`) every time unless the user says otherwise.

## Learned Workspace Facts

- Single-page marketing site: React 19, Vite 7, Tailwind CSS 4, Framer Motion; no client-side router on the public site.
- Stitch design tokens live in `src/index.css` (background `#f9f9fc`, surface `#ffffff`, ink `#1a1c1e`, primary `#005f56`, primary-container `#0d7a6f`, secondary `#765842`; Manrope headlines + Work Sans body). Token layer also defines a type scale (`--text-display/h1/h2/h3`), elevation scale (`--shadow-1..4`), radius family, fluid `--section-y`, and `--ease-out`; buttons share one base rule with per-variant overrides.
- `src/utils/cn.ts` uses `extendTailwindMerge` to register the custom `text-*` font-size scale separately from the custom `text-*` colours. Without it tailwind-merge treats `text-h2` as a colour and drops it when combined with `text-ink` — that silently rendered every section heading at 16px. Any new `text-<name>` size or colour utility must be added to those class groups.
- Public section order and index markers: Hero → TrustStrip (credential band, static `doctor` data) → Treatments `01` (`#services` skin cards + `#hair-services` compact rows) → CareStandards `02` → ClinicDoctor `03` (`#about`, `#doctor`) → Outcomes `04` (`#results`) → Aesthetics `05` (`#aesthetics`, compact rows) → Gallery `06` (`#gallery`) → SocialProof `07` (`#testimonials`) → Faq `08` → Visit `09` (`#contact`) → GeneralEnquiry (`#enquiry`, `#location`) → Footer → WhatsAppFloat. Backgrounds alternate surface / surface-container-low and must never repeat across adjacent sections.
- Treatment presentation encodes the skin-first hierarchy: skin uses image-led `TreatmentCard` (4 shown on mobile, 6 from `sm`, rest behind a `.disclosure-btn`); hair and aesthetics use the compact `TreatmentRow`. Both live in `src/components/ui/TreatmentCard.tsx` and use a stretched heading-button (`::after` inset 0) so the card is fully tappable while keeping a real `<h3>` and a short accessible name — never nest an `<article>`/`<h3>` inside a `<button>`.
- Gallery is a snap-scrolling horizontal rail below `sm` and a grid from `sm` up; the CMS can hold many photos, so stacking them costs ~2,000px of mobile scroll.
- `useActiveSection` drives nav state from scroll position (reading line at `navHeight + 96`), not from click. It uses direct measurement rather than IntersectionObserver because section heights vary hugely and a tall section otherwise wins permanently.
- Clinic business content is centralized in `src/data/clinic.ts` with CMS overrides via `clinic_settings` (maps, WhatsApp float/main URLs, social/reviews URLs, phones table); brand assets `/clinic-logo-mark.png` and `/favicon.png`; floating WhatsApp and form handoff both use `whatsappFloat` (9706929329, same as main clinic WhatsApp).
- Doctor profile in `clinic.ts`: Dr. Prakash Acharya, Board Certified Dermatologist, NMC Reg. No. 12549 (Specialist, Dermatology), MD Dermatology Kathmandu University (2020), MBBS Tribhuvan University Maharajgunj Medical Campus (2011), site `https://drprakashacharya.com.np/`; portrait at `/images/doctor/dr-prakash-acharya.png`.
- Hero: full-bleed clinic poster served per breakpoint — `clinic-hero@1920.jpg` at `lg`+, `clinic-hero.webp` (44KB) below it, `clinic-hero.png` only as the no-WebP fallback. `index.html` preloads are media-scoped; a single unscoped preload made desktop fetch the PNG *and* the JPEG. Subtle bottom/left overlay; bottom-aligned frosted `.hero-main-card` + `.hero-info-card`; mobile `.hero-media` is sized by `aspect-ratio: 3/4` with a matching ratio-derived `padding-top` on `.hero-shell` (not fixed rem values, which only aligned at 375px); `object-position` ~42–46% keeps the clinic sign and receptionist in frame.
- Outcomes (`#results`) uses illustrative photography fallbacks when CMS cases are empty.
- Known outstanding: `public/clinic-logo-mark.png` and `public/favicon.png` are both 92KB PNGs (identical bytes) for a ~46px mark — ~184KB of avatar for two slots. Needs offline image tooling to resize; no converter is installed in this environment.
- Public build uses `vite-plugin-singlefile`; admin is a separate Vite project in `admin/` (dev port 5174); production deploys via `vercel.json` to Vercel (public at root, admin SPA at `/admin`, `pokhara-skin-and-hair-clinic.vercel.app`).
- Supabase backs appointment persistence, admin Auth, and Resend email edge functions with separate patient vs admin HTML templates for bookings and enquiries; `appointments.deleted_at` soft-delete is live (staff trash/restore via UPDATE; patient fields immutable after insert; no hard DELETE for staff).
- Admin SPA routes: `/dashboard`, `/queue`, `/bookings`, `/enquiries`, `/analytics`, `/treatment-options`, `/settings`, `/services`, `/testimonials`, `/results`, `/gallery`, `/hero`, `/doctor`; login via `src/lib/admin-url.ts` (`VITE_ADMIN_URL`); patient fields read-only, status/`internal_notes`/`deleted_at` editable; bookings/enquiries support trash/restore views; follow-up queue and detail use WA scripts from `admin/src/lib/follow-up-scripts.ts` (default/confirm/missed/completed); ClinicSettings manages phones + WhatsApp channels; CMS singletons `clinic_settings` and `doctor_profile` (id=1) use `.maybeSingle()` with upsert-on-empty (missing seed rows caused 406/blank pages).
- Public booking (`#contact`) and general enquiry (`#enquiry`, `GeneralEnquiry.tsx`) forms persist to `appointments` with `form_type` and send Resend emails; after a successful submit they also open a prefilled WhatsApp chat to `whatsappFloat` (9706929329) via `src/lib/whatsapp.ts` (BookFab removed; WhatsApp float only); forms use borderless `.field-input` on surface-container-low inside `.form-card` white panels; location map is a plain Google Maps embed iframe (not the Maps JS API).
